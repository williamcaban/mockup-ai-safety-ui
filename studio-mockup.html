Session Stitcher

P0 · Reconstructs multi-turn conversations from raw OTel/MLflow spans · Foundation for all downstream analysis

⚠️
The Problem
AI applications emit telemetry as a raw stream of individual spans — one per LLM call, tool call, or retrieval step. Each span only knows its own trace_id. Nothing in the raw stream says "these 24 spans are all part of the same 6-turn conversation with user U-001." Without stitching you can observe individual API calls but never answer: where in the conversation did the user give up?

Behavioral Signal Extractor

P0 · Extracts 5 lightweight behavioral signals from stitched sessions · Non-LLM · <100ms per session · Feeds Funnel Analyzer & Drift Detector

🧠
What it does
Receives a Session object from the Stitcher and extracts 5 behavioral signals — all without calling an LLM. Signals are computed using TF-IDF cosine similarity and a curated frustration lexicon. Output is a BehavioralSignals object annotated onto the session, consumed directly by the Funnel Analyzer, Complexity Bucketer, and Drift Detector.

① Reprompt Detection
274 sessions flagged
For each consecutive turn pair (n-1, n): compute cosine similarity of user messages via TF-IDF. If similarity > 0.60 AND turn n-1 has a completed LLM span → reprompt flagged. Fallback: lexicon hit on frustration words regardless of similarity.

② Intent Continuity
99 sessions shifted
Compares TF-IDF vector of turn 0 (user's opening message) against all subsequent turns. If similarity to turn 0 drops below 0.25 at any point → intent shift recorded with the turn index. Stable intent across all turns → score of 1.0.

③ Sentiment Proxy
386 declining
Per turn: count lexicon hits in user message, compute frustration score (hits / word count). Linear regression slope across per-turn scores → session trend. Slope > 0.1 = DECLINING · < -0.1 = RISING · else STABLE. No LLM call.
